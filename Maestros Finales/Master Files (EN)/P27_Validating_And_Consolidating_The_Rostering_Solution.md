## Confirming that the solution is ready to be validated

After reviewing coverage, conflicts and feasibility, the next step is to decide whether the Rostering solution can already be considered sound enough. Validating does not just mean giving an administrative clearance. It means declaring that the assignment of personnel is already consistent, understandable and usable as an approved basis.

Use this quick start when you've already executed the Rostering calculation, analyzed its result, and need to formally close the solution before continuing with its consolidation.

Before you start, make sure that:
1. You've already run the Rostering calculation on P25.
2. You've already reviewed conflicts, coverage and viability at P26.
3. You have already corrected the main problems or already understand why the remaining conflicts are acceptable.
4. You know what concrete solution you're going to validate.

For this quick start, use this reference case:

> **I am going to validate the Rostering solution of line L1 because the assignment already covers the work reliably enough and I want to consolidate it as an approved reference.**

To confirm that the solution is ready for validation:
1. Open the Rostering solution that you will use as a reference.
2. Check the job coverage one last time.
3. Confirms that the main conflicts have already been resolved or diagnosed.
4. Review whether the resulting allocation remains consistent with:
   1. Rostering's rules,
   2. actual availability of staff,
   3. operational secondment,
   4. and the solution inherited from Scheduling.
5. If you detect an unsolved major problem, don't validate the solution yet.
6. If the base is already stable, continue to the validation step.

For the reference case, do not continue until you can state:
1. The work of L1 is already covered or the remaining gaps are understood.
2. The solution is operationally defensible.
3. You no longer need to make structural changes before you pass it.

When you finish this section, you should be clear whether the solution already deserves formal validation.

## Executing the validation of the personnel solution

Once the solution is stable enough, you need to run the validation. This step marks the closing of the Rostering calculation and review phase, and turns the solution into an approved reference within the workflow.

Before starting this section, make sure that:
1. You've already decided that the solution is valid.
2. You no longer need to recalculate or adjust rules before passing.
3. You know that validating means freezing the solution as an approved reference.

To validate the Rostering solution:
1. From the view of the solution or from the main table, open the corresponding action menu.
ref: P27_Imagen1.png | full
2. Select the **Validate** action.
3. Check the final summary of the solution before confirming.
4. Confirm the validation when the system requests it.
5. Checks that the status of the solution changes to the corresponding approval status.
6. Check that the solution is no longer treated as a provisional version of work.
7. If your stream uses specific permissions to approve, confirm that the validation was recorded correctly.

For the reference case, make sure that:
1. The L1 solution changes status after validation.
2. The system already recognizes it as an approved version.
3. The solution is no longer treated as an iteration still open.

When you finish this section, you should have a formally validated Rostering solution.

## Consolidating the solution as an operational reference

After validating, you need to consolidate the solution. Consolidating means treating that version as the approved reference for the next level of the process. From here, the solution should no longer be managed as a test, but as the serious and traceable basis for staff assignment.

Before starting this section, make sure that:
1. The solution is already validated.
2. You know if this will be the current reference or an approved version pending later use.
3. You can now differentiate an approved solution from a solution under review.

To consolidate the validated solution:
1. Check the name and description of the solution.
2. If necessary, update the description to make it clear:
   1. what context it covers,
   2. what period it represents,
   3. and why it was approved.
3. Checks that the validated solution is clearly distinguishable from previous drafts, tests or iterations.
4. If your internal process requires it, record that this version becomes the reference for the next step.
5. It retains previous versions as historical, but avoids treating them as equivalent to the approved solution.

For the reference case, make sure that:
1. The validated L1 solution is clearly distinguished from tests or intermediate versions.
2. The team can identify it as the right reference.
3. The traceability of the approval is clear.

When you finish this section, you should have an approved and recognizable solution as a serious Rostering reference.

## Checking what is blocked and what would require a new iteration

Before closing, you need to be clear that validating a solution does not mean that the possibility of improving it disappears. It means that that particular version has already been closed. If you need an improvement or a background adjustment later on, the correct thing will be to open a new iteration or a new working solution, not to uncheck the approved version.

Before continuing, make sure that:
1. The solution is already validated.
2. You know what parts of the job were closed.
3. It is clear to you that future improvements must be traced as new iterations.

To make post-validation governance clear:
1. Treat the validated solution as a closed reference.
2. Avoid modifying it directly as if it were still a draft.
3. If you notice a future improvement:
   1. creates a new iteration,
   2. or opens a new calculation and review cycle.
4. It retains the validated version as a point of historical comparison.
5. If your team needs to audit decisions, use this solution as an approved baseline.

For the reference case, finish this section only when you can state:
1. The validated version of L1 is now closed.
2. Any future improvement will be made through a new iteration.
3. Traceability between calculation, review and approval is preserved.

When you finish this section, you should be clear about what it means to consolidate a solution and how to avoid losing control over the versions.

## Leaving the solution ready for the next level of the process

The last step is to mentally prepare the transition. From here, the Rostering solution is no longer in the technical calculation phase, but is in the phase of use, consolidation or transfer to the next appropriate operating process.

Before you finish, make sure that:
1. You've already validated the solution.
2. You've already treated her as a consolidated reference.
3. You know if the next step will be:
   1. communicate it,
   2. integrate it,
   3. audit it,
   4. or prepare a new future iteration.

To close this quick start correctly:
1. Check the state of the solution one last time.
2. It confirms that this is no longer a provisional calculation.
3. Check that the computer could identify this version as approved.
4. If your process requires it, record the transition to the next operating level.
5. It retains the solution as a stable reference for future comparison.

For the reference case, finish this quick start only when you can say:
1. The L1 Rostering solution is already validated.
2. It has already been consolidated as an approved reference.
3. The next step is no longer to calculate, but to use, review or evolve that base in a controlled manner.

When you finish this section, you should have a validated, consolidated and ready Rostering solution to serve as a stable process reference.
